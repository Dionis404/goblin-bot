# API: топ-500 лидерборда тикетов SFL

## Доступ

Эндпоинт живёт в контейнере `goblin-api`, в той же docker-сети `shared-net`,
что и сайт (`docker-compose.yml`). Доступ — по имени контейнера, без внешнего
хоста/порта, точно так же, как сайт уже ходит в `/api/auctions`, `/farms` и
другие существующие эндпоинты этого же API:

```
http://goblin-api:8000/api/tickets/top500
```

Снаружи docker-сети этот адрес не резолвится — эндпоинт не публичный, дёргать
его нужно только с сервера/бэкенда сайта, который сидит в той же сети.

## GET /api/tickets/top500

Возвращает снэпшот глобального топ-500 лидерборда тикетов Sunflower Land —
либо самый свежий, либо исторический (на конкретный момент времени).

### Обновление данных

Бэкенд (`goblin-bot`) сам, независимо от сайта, раз в час опрашивает игровой
API SFL и складывает полный топ-500 в БД **новой пачкой строк** (старые
никогда не перезаписываются и не удаляются — история хранится вся). Значит:

- Данные всегда "с опозданием" до ~1 часа от реального состояния борда.
- Каждый вызов `/api/tickets/top500` просто читает из БД уже готовый
  снэпшот — запрос быстрый, наружу к SFL ничего не ходит.
- Если нужно узнать, насколько свежие данные — смотри `updated_at` в ответе.

### Параметры запроса

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `at` | string (ISO 8601, например `2026-08-25T03:00:00Z`) | нет | Если указан — вернуть снэпшот, ближайший к этому моменту, но не позже него ("как выглядел топ-500 N часов/дней назад"). Без параметра — самый свежий снэпшот. |

Примеры:

```
GET /api/tickets/top500                          — текущий топ-500
GET /api/tickets/top500?at=2026-08-25T03:00:00Z  — топ-500 на 25 августа, 03:00 UTC (или ближайший снэпшот ДО этого момента)
```

Если снэпшотов раньше указанного `at` нет вообще (например, `at` — точка до
первого деплоя) — вернётся пустой борд, так же как при полном отсутствии
данных (см. ниже).

### Пример ответа

```json
{
  "updated_at": "2026-08-26T21:00:03.123456+00:00",
  "leaderboard": [
    {
      "rank": 1,
      "farm_id": 147426,
      "game_username": "n3paa",
      "tickets": 4552
    },
    {
      "rank": 2,
      "farm_id": 15223,
      "game_username": "Bacon",
      "tickets": 4552
    }
  ]
}
```

`updated_at` в ответе — это `taken_at` **того самого снэпшота**, который
реально вернули (а не текущее время запроса). При использовании `at` смотри
именно на это поле, чтобы понять, на какой точный момент показаны данные —
он может немного отличаться от запрошенного `at` (снэпшоты берутся раз в час).

### Поля

| Поле | Тип | Описание |
|---|---|---|
| `updated_at` | string (ISO 8601) \| `null` | Время сбора возвращённого снэпшота (UTC). `null`, если подходящих снэпшотов нет вообще. |
| `leaderboard` | array | Список из 500 записей (может быть короче/пустым, пока не готов первый снэпшот), отсортирован по `rank` по возрастанию. |
| `leaderboard[].rank` | int | Место в глобальном лидерборде тикетов, 1 — лучший. |
| `leaderboard[].farm_id` | int | ID фермы в игре Sunflower Land. |
| `leaderboard[].game_username` | string \| `null` | Игровой ник (может отсутствовать). |
| `leaderboard[].tickets` | int | Количество тикетов на момент снэпшота. |

### Сравнение "было / стало" (изменение топа во времени)

Отдельного эндпоинта для дельты (кто поднялся/опустился) нет. Чтобы
показать это на сайте — сделай два вызова и сравни на своей стороне:

```
GET /api/tickets/top500                          — сейчас
GET /api/tickets/top500?at=2026-08-19T03:00:00Z  — неделю назад
```

Сравнивай по `farm_id`: у каждой фермы есть `rank` в обоих ответах —
разница между ними и есть изменение места.

### Ошибки

Эндпоинт ничего специально не валидирует и не кидает 4xx/5xx в штатных
сценариях — если подходящих снэпшотов нет, просто вернёт `{"updated_at":
null, "leaderboard": []}`.

## Важно: это не то же самое, что личный трекинг игрока

В боте есть отдельный, не связанный с этим эндпоинтом механизм — игрок может
включить себе персональное отслеживание места (команда `/tracking_lb`), и раз
в неделю (ночь с воскресенья на понедельник, 03:00 МСК) в Telegram-группу
уходит сводка по тем, кто попал в топ-1200. Эти данные **не отдаются через
API** и на сайт не идут — только `/api/tickets/top500` содержит "сырой" топ-500,
который можно показывать на сайте.
